## CO-ACTIVATIONS
#topic_core 

Эта ось ловит **устойчивые "режимы мышления/контекста"**: какие концепты обычно вспыхивают вместе (или подавляют друг друга) в близком окне времени **по множеству эпизодов/трейсов** (то есть это глобальная статистика, а не "память одного эпизода").

Если такие наборы повторяются, мы превращаем их в отдельный концепт-паттерн/ансамбль `E` (реификация ансамбля) — и дальше используем `E` как новый концепт: его входной контекст и типичные продолжения уже известны из истории.

> [!definition]
> **Temporal window**
> `Δt` — максимальный интервал, в пределах которого активации считаются "совместными" (co-activation).
^def-TemporalWindow

## Pairwise Index 
#topic_details 

Мы храним **сырые ко-активации (k=2,быстрый индекс):**
для каждого узла `x` список "частых соседей" `y` с весом совместной активации/ингибиции. Этот слой нужен **как быстрый proposal engine**: он генерирует кандидатов, из которых потом собираются higher-order паттерны (2..K узлов).


### Операции оси (Ascend / Descend)
#topic_core 

> [!definition]
> **Ascend: `RECOGNIZE_PATTERN` (CONTEXT → PATTERN)**
> Вход: текущий контекст `S` (|S| = 1..K активных узлов, обычно K≤5).
> Выход: top-K паттернов `E`, которые лучше всего "попали" в `S` (по покрытию/пересечению и весам).
^def-RecognizePattern

> [!definition]
> **Descend: `COMPLETE_CONTEXT` (PATTERN → NODES_CORRELATIONS)**
> Вход: паттерн `E` (или `S`, если сначала сделали Ascend).
> Выход: ранжированный список узлов:
^def-CompleteContext

- **Positive co-activation (положительная ассоциация):** узлы часто активны вместе узлы, с высокой положительной ассоциацией `P(y | S)`
- **Negative co-activation / inhibition (отрицательная ассоциация):** когда один активен, другой обычно не активен/подавлен, с высокой отрицательной ассоциацией `P(¬y | S)` (анти-коактивация/ингибиция)

### Как это работает по шагам
#topic_details 

#### Шаг 1 — Собираем окна активности

В каждом эпизоде/трейсе выбираем временное окно **длины `Δt`** (или `W` шагов) и фиксируем:

- `A(Δt)` = активные узлы в окне,
- `I(Δt)` = подавленные узлы в окне (если есть).

> [!example]
> **Пример окна:**
> Активны: `{Кофе, Усталость, Работа}`
> Подавлены: `{Сон}`

#### Шаг 2 — Обновляем "сырые" ко-активации (pairwise)

Для всех пар внутри `A` усиливаем совместность:
`Кофе ↔ Усталость`, `Усталость ↔ Работа`, `Кофе ↔ Работа`.

Если есть `I`, усиливаем анти-связи:
`Усталость ⟂ Сон`, `Кофе ⟂ Сон`.

> [!note]
> Интуиция: это "карта соседей", которая быстро подсказывает кандидатов для сборки паттерна и для completion по частичному контексту.

#### Шаг 3 — Рождение higher-order паттернов и реификация `E`

Из окна `A` выбираем небольшое ядро `A_core` (например top-активные узлы) и формируем кандидатов наборов размера 2..K.

## HyperPatterns (k=3..5, реифицированные ансамбли)
#topic_details 

Гипер-отношения/ансамбли `E` с `members=(2..К)` и операциями распознавания/достройки.

Отдельное хранилище объектов:

(formal_id:: hyperpatterns.storage.schema)
```
P = {members: sorted tuple of node_ids (k=2..K), support, score, predicts/suppresses...}
```
^spec-HyperPatternsStorage

> [!important]
> **Ключ:** каноническое представление набора
> `key = (id1,id2,id3)` (отсортировано) → **одна запись** на набор (без дублирования).

## Pattern Indexing (Inverted index)
#topic_details 

Чтобы быстро находить паттерны по частичному набору:

- `Index[node_id] -> list(pattern_ids)` ("в каких паттернах участвует узел")

Опционально быстрее:

- `IndexPair[(a,b)] -> list(pattern_ids)` для k≥3 (ускоряет запросы по двум узлам)

> [!note]
> Это sparse, потому что паттернов мало (мы их жёстко режем по score/support/устареванию).
